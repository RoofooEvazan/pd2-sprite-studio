PD2 Sprite Studio

An editor for Diablo II / Project Diablo 2 graphics that reads straight from the game's MPQ archives. You can edit character, monster and item sprites pixel by pixel in the game palettes, turn 3D models into animated sprites, and cut 3D scenes from Blender or 3ds Max into DT1 map tiles and a DS1 map piece. Everything saves back out in the game's own formats, and AI assistants can drive it over MCP while you watch.

Format accuracy

Every codec is pure TypeScript and was checked against the game's own files before any UI used it. The image below is the Act 1 Cathedral courtyard, rendered from its real DS1 and DT1s by the app's own decoders and placement code. The same code draws the Tile Maker's previews.

DT1 re-encodes that aren't byte-exact are still pixel-identical; they just use equivalent run choices. The 52 DS1s that aren't byte-exact are older-version maps that differ by a few bytes; the Tile Maker writes v18, which is exact. Excluded: a 72-byte COF stub that is corrupt in vanilla D2 (amblxbow.cof) and 6 legacy v4 DT1 leftovers the game doesn't use. Run the checks with npm test.

How it works

Electron app with a React + TypeScript UI. File formats live in a dependency-free core that also runs under Node for the tests.

src/core

Formats

  • MPQ v1 reader with a PKWARE “explode” port, zlib, encrypted and fix-key files, and layered archive priority (PD2 over vanilla)
  • DCC decoder/encoder with the equal-cell stream, and a cell-grid anchor search so edits don't degrade original art
  • DC6, COF, animdata.d2, DT1 and DS1 (all versions, trailing data preserved)
src/core

Editing logic

  • COF layer compositing with draw effects
  • Edit transfer between frames by region tracking
  • Perceptual (Lab) palette matching, shading ramps, ramp swaps, outline and clean-up
  • Render import: facing mapping (8↔16), frame resampling, ground point, dithering
src/renderer

3D (three.js)

  • Game camera: orthographic, 30° elevation, 45° azimuth; +Z faces down-left (direction 0)
  • FBX, glTF/GLB and OBJ loaders with texture resolution; animation clips; bone attachment
  • Tile scenes at 1 unit = 1 tile (160 px), with a world-position pass for wall slicing

Tile Maker pipeline

The old way was to render a scene and cut the walls into tiles by hand. This does the cutting automatically.

  1. Import and line up. The model is set on the grid at “1 tile = N units” (auto-guessed for Blender metres or 3ds Max centimetres). You can stand Z-up models upright, turn them in 90° steps and move them by whole tiles.
  2. Render layers. Floor, wall, lower-wall and roof parts render separately through the exact tile camera, where world (X, Y, Z) maps to pixels as ((X−Z)·80, (X+Z)·40 − Y·98). A float render target also records each wall pixel's world position and which way its surface faces.
  3. Slice. Floors are sampled into the 25 diamond blocks per 160×80 tile. Each wall pixel goes to the grid line its surface runs along (the nearest line for flat tops): X = n gives a left wall (orientation 1), Z = n gives a right wall (orientation 2). Wall geometry below the ground becomes lower walls (16/17, directions 6/7). Roofs become orientation-15 tiles raised to their height.
  4. Walkability. Low wall geometry marks the subtile it stands on as blocked (0x07), stored in the same row order the game's tiles use.
  5. Write. Identical tiles are shared, then indexes are assigned from a chosen start (64 per main index). It writes DT1 v7/6 files split by kind, plus a DS1 v18 map piece listing them, with floors in layer 1 and walls, lower walls and roofs filling up to 4 wall layers.

AI assistants (MCP)

New in 1.1: the app can serve the Model Context Protocol, so an assistant such as Claude can work in the open app while you watch. Every change goes through the same code as the UI: it shows up live, is one undo step, and exports like a hand edit. Tool results include pictures (the frame, a sheet, or the map drawn with the game's rules), so the assistant can check its own work.

Sprites

Find, edit, export

  • search_sprites, open_animation, open_item, set_layer (body part, style, new style code)
  • view_frame, view_sheet, read_pixels, palette (nearest colours, shading ramps)
  • recolor_material, replace_color, hsv_shift, draw_pixels, draw_shape, outline, import_image
  • transfer_edits carries one frame's edit through the animation; undo / redo; export_pd2, export_image
Tile Maker

Build and split scenes

  • tiles_add_block (box, cylinder, cone, sphere, ramp in tile units) or tiles_import_model
  • tiles_list_parts, tiles_set_role, tiles_settings, tiles_clear
  • tiles_split returns tile counts and the map as the game draws it; tiles_save writes the DT1s and DS1
Connection

Local only

  • Streamable HTTP on 127.0.0.1:41730/mcp; requests from web pages (other origins or hosts) are refused
  • Claude Desktop and other stdio clients use a bundled bridge run by the app's own executable, so nothing else needs installing
  • Plus get_state, go_to_screen and screenshot_app

Known limits

Please look closely at these.

  • Not yet tested in the game. The exported DCC, DC6, DT1 and DS1 files are verified by decoding and re-rendering only. They still need a run in PD2 single player (PlugY / -direct -txt) and in ds1-studio.
  • Online use is unconfirmed. PD2's rules forbid tools that “tamper with the game”; whether client-side graphics changes count hasn't been asked yet.
  • Tile types. Floors, left/right walls, lower walls and roofs are generated. Corners, doors, shadows and animated tiles are not yet.
  • AI assistants work best with the high-level tools. Recolours, edit transfer, clean-up and Tile Maker scenes come out well; pixel art drawn from scratch by an assistant is rough. While the MCP switch is on, any program on the PC can drive the app.
  • DCC 4-colour cells. Cells with more than 4 colours (common in 3D shading) are reduced at export. The editor flags them in red.
  • No real Blender or 3ds Max files tested yet. Tests used equivalent GLB and OBJ written by scripts. Draco-compressed GLB isn't supported.
  • Walk flags and cell values are inferred. The subtile flag layout and DS1 “tile present” values copy patterns found in the game's files, not a published spec.

Running it

The Windows installer (PD2-Sprite-Studio-Setup-1.1.0.exe, about 95 MB, unsigned) installs per-user with Start menu and desktop shortcuts. On first run it looks for the game in C:\Program Files\Diablo II and its ProjectD2 folder; other locations can be set in Settings. It never modifies the game install: exports go to a separate folder with the game's own data\global\… layout.

The source and the installer are available from the author on request.

# from the source folder (Node 20+)
npm install
npm run dev          # run with hot reload
npm test             # format round-trips against your game files
node scripts/testMcp.cjs  # MCP server end to end (after npm run build)
npm run dist         # build the Windows installer → release/
npx tsx scripts/webdev.ts   # UI in a browser on :5198
